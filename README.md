# Method Network — панель серверов

Локальная веб-панель мониторинга и управления Linux-серверами по SSH.
Работает на вашем компьютере (macOS, Windows, Linux) и открывается в браузере.
На серверы **ничего не устанавливается**: панель подключается к ним как обычный
`ssh`, читает `/proc` и выполняет команды.

## Быстрый старт

Нужен клиент OpenSSH (`ssh`, `ssh-keygen`, `ssh-keyscan`). В macOS и Linux он
обычно уже есть, в Windows 10/11 — тоже (иначе: *Параметры → Система →
Дополнительные компоненты → Клиент OpenSSH*).

### Windows

1. Скачайте репозиторий (*Code → Download ZIP*) и распакуйте.
2. Дважды щёлкните `start-windows.bat`. Если установлен [Go](https://go.dev/dl/),
   батник соберёт панель сам; если нет — положите рядом готовый
   `server-panel.exe` (собирается командой `./build.sh` на любой системе с Go).
3. Откроется <http://127.0.0.1:7780>.

Автозапуск при входе в Windows: `start-windows.bat autostart` (окно панели
стартует свёрнутым), выключить — `start-windows.bat noautostart`.

### macOS

Дважды щёлкните `ServerPanel.command` — он соберёт панель (нужен Go:
`brew install go`) и откроет её в браузере. Автозапуск в фоне:

```bash
./ServerPanel.command autostart
```

Выключить — `./ServerPanel.command noautostart`. Лог — `~/.server-panel/panel.log`.

### Linux

```bash
go build -trimpath -o server-panel . && ./server-panel
```

Автозапуск через systemd (пользовательская служба):

```bash
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/server-panel.service <<EOF
[Unit]
Description=Method Network Panel
[Service]
ExecStart=$PWD/server-panel -no-open
Restart=on-failure
[Install]
WantedBy=default.target
EOF
systemctl --user enable --now server-panel
```

### Сборка под все системы

```bash
./build.sh            # dist/server-panel-{darwin,linux,windows}-{amd64,arm64}
```

Зависимостей, кроме стандартной библиотеки Go, нет; cgo не используется.

## Подключение серверов

При первом запуске панель предложит два пути:

- **По адресу и паролю** — «Добавить сервер»: адрес, пользователь, пароль от
  хостинга. Панель покажет отпечаток ключа сервера (его можно сверить в консоли
  хостинга), один раз войдёт по паролю, добавит на сервер **свой ключ** и дальше
  будет входить только по нему. Пароль нигде не сохраняется. Если хостинг не
  пускает root по паролю — используйте обычного пользователя с `sudo`.
- **По SSH-ключу** — тот же мастер, но вместо пароля выбирается ключ из `~/.ssh`
  или ключ панели (его публичную часть можно скопировать на странице
  «Управление» и положить в `~/.ssh/authorized_keys` на сервере).
- **Из `~/.ssh/config`** — панель найдёт все `Host` (включая `Include`) и
  предложит отметить, какие показывать. Сам файл панель не меняет.

На странице **«Управление»**: порядок в списке, названия, группы, проверка
входа, смена адреса или ключа, скрытие, отключение оповещений и удаление (при
удалении можно заодно убрать ключ панели с сервера).

## Что умеет

- **Все серверы** — карточки со статусом, CPU, памятью, диском, трафиком,
  группы; сводка «на связи / нагрузка / трафик / требуют внимания».
- **Обзор сервера** — живые графики CPU, памяти, сети, диска, load average и
  TCP-соединений за 5 мин…30 дней; ядра, файловые системы, интерфейсы.
- **Процессы** — CPU по процессам, поиск, сортировка, завершение (TERM/KILL).
- **Службы systemd** — состояние, запуск/остановка/перезапуск, автозапуск;
  службы с ошибкой — сверху.
- **Журнал** — journalctl с фильтром по службе и уровню, режим «Следить».
- **Сеть** — открытые порты с процессами, соединения, самые активные IP.
- **Docker** — контейнеры, их CPU/память, логи, управление.
- **VPN** — xray, sing-box, hysteria, AmneziaWG/WireGuard, mtg, OpenVPN и др.:
  состояние, порты и число клиентов, пиры WireGuard, перезапуск, журнал, конфиг.
- **Файлы** — просмотр, редактор конфигов (проверка JSON, защита от перезаписи
  чужих изменений), загрузка и скачивание; режим «как root» через sudo.
- **Система** — доступные обновления (отдельно — безопасности), нужна ли
  перезагрузка, установка обновлений фоновым заданием, настройки sshd, входы
  по SSH за сутки, fail2ban, ufw.
- **Терминал** — полноценный терминал в браузере (xterm.js); в Windows —
  через ConPTY (Windows 10 1809+).
- **Команды** — одна команда на нескольких серверах, одинаковый вывод
  группируется.
- **Оповещения** — системные уведомления (macOS, Windows, Linux) и Telegram:
  нет связи, высокая нагрузка, заполнен диск, упала служба или VPN; сообщение
  о восстановлении, журнал событий.

## Где хранятся данные

Всё — только на вашем компьютере, в `~/.server-panel`
(в Windows — `%USERPROFILE%\.server-panel`):

| Файл | Что внутри |
|---|---|
| `settings.json` | серверы, названия, группы, порядок, правила оповещений и токен Telegram-бота |
| `alerts.json` | состояние и журнал оповещений |
| `keys/id_ed25519` | ключ панели для серверов, добавленных по паролю |
| `known_hosts` | закреплённые ключи этих серверов |
| `history/` | история графиков |

Другой каталог — флаг `-data`.

## Флаги

| Флаг | По умолчанию | |
|---|---|---|
| `-listen` | `127.0.0.1:7780` | адрес веб-интерфейса |
| `-interval` | `2` | секунд между замерами |
| `-no-open` | — | не открывать браузер при запуске |
| `-data` | `~/.server-panel` | каталог данных |
| `-notify=false` | — | не отправлять оповещения, только журнал |

## Как это устроено

- Один постоянный SSH-поток на сервер: скрипт на `sh` раз в N секунд печатает
  сырые счётчики из `/proc`, скорости и проценты считает панель.
- В macOS и Linux команды управления идут через то же соединение
  (`ControlMaster`) и отвечают за ~100–200 мс. В Windows OpenSSH этого не
  умеет, поэтому каждое действие — отдельное подключение.
- Для пользователя не root привилегированные действия выполняются через
  `sudo -n` (если sudo без пароля разрешён).
- Ключ хоста для серверов, добавленных через мастер, закрепляется
  (`StrictHostKeyChecking=yes`): если его подменят, панель откажется
  подключаться.
- Обновления пакетов запускаются через `systemd-run` и продолжают работать,
  даже если связь прервётся.
- xterm.js лежит в `web/vendor` (5.5.0 и addon-fit 0.10.0, лицензии MIT рядом).

## Безопасность

- Веб-интерфейс слушает только `127.0.0.1`.
- Каждый запуск создаёт случайный токен; API без него отвечает 401, а запросы
  с чужим `Host` — 403 (защита от CSRF и DNS rebinding).
- Имена служб, контейнеров, PID и сигналы проверяются по белым спискам;
  произвольные команды выполняются только из «Терминала» и «Команд».
- Файлы записываются атомарно с сохранением прав и владельца; удалять папки
  верхнего уровня, `.ssh`, `authorized_keys`, `/etc/ssh`, `/etc/sudoers` из
  панели нельзя.
- Действия, которые могут оборвать доступ (остановка ssh, сети), требуют
  отдельного подтверждения.
